# Zippy — Implemented Features & Technical Implementation Guide

This document catalogs every implemented feature in the **Zippy Online Food Ordering Platform** (`pooja_project/`) and details how each capability is engineered across the PHP service layer, relational database, computational engines, REST/AJAX/SSE endpoints, and frontend portals.

---

## 1. System Architecture & Engineering Foundations

### 1.1 Four Role-Based Portals & Service Separation
- **Master Launchpad ([`index.php`](../index.php)):** Presents direct portal launch links, real-time MySQL health diagnostics via `checkDbStatus()` ([`config/database.php`](../config/database.php)), platform dish/order counts via `OrderService::getPlatformOverviewCounts()`, and—when `APP_DEMO_MODE` is enabled—a concurrent multi-actor session status panel via `getAllPortalActors()` ([`config/config.php`](../config/config.php)).
- **Domain Service Layer (`includes/Services/`):** Views handle layout, CSRF checks, and escaping (`e()`, `jsJson()`), while business logic and parameterized PDO queries live in five strictly typed (`declare(strict_types=1);`) services:
  - [`CatalogService.php`](../includes/Services/CatalogService.php) — storefront discovery, nutrition/allergen filtering, dish favorites (`user_favorites`), live search, category/dish/customization/mood CRUD, and soft archival.
  - [`OrderService.php`](../includes/Services/OrderService.php) — ACID checkout (with FCFS scheduled-slot capacity throttling, dynamic DB coupons, loyalty points, and Indian geofenced distance pricing), 60-second self-cancellation, tracking, GST invoices, order ratings, FAQ/threaded customer support tickets, KDS lanes/station checklists/KOT, and admin batch order actions.
  - [`FleetService.php`](../includes/Services/FleetService.php) — rider duty toggles, FCFS/manual order claims, 6-digit OTP verification + loyalty awards, GPS route interpolation, Rider SOS / Failed Delivery exception logging & Admin re-dispatch, and fleet payouts.
  - [`FinanceService.php`](../includes/Services/FinanceService.php) — inward/outward money ledger, rider COD vault deposits, daily Z-Report cash drawer closures, kitchen payroll, and executive BI datasets.
  - [`AdminService.php`](../includes/Services/AdminService.php) — operations dashboard KPIs, immutable audit trail filtering/export, support ticket desk, dynamic coupon CRUD, FAQ CRUD, review moderation, user RBAC directory, and customer profile/dietary updates.
- **Shared View & Query Helpers:**
  - [`includes/functions.php`](../includes/functions.php) provides PDO wrappers (`dbQuery()`, `dbFetchAll()`, `dbFetchOne()`, `dbFetchVal()`, `dbTransactional()`), DB-backed coupon evaluation (`getAvailableCoupons()`, `validateCouponForSubtotal()`), billing (`calculateBillTotals()`), FCFS allocation (`autoAllocateReadyOrdersFcfs()`), `transitionOrderStatus()`, Bengaluru geofence & Haversine distance pricing (`getIndianServiceZones()`, `calculateHaversineDistanceKm()`, `calculateDistanceDeliveryFee()`, `validateServiceableLocation()`), loyalty ledger helpers (`calculateLoyaltyPointsEarned()`, `awardLoyaltyPointsForOrder()`, `refundLoyaltyPointsForOrder()`), and dietary helpers (`getDishAllergenOptions()`, `getDietaryPreferenceOptions()`, `getUserDietaryPreferences()`).
  - [`includes/view_helpers.php`](../includes/view_helpers.php) centralizes KDS ticket rendering (`renderOrderCard()`, `formatKdsWaitTime()`, `getKdsPriorityBadge()`), dietary conflict alerts (`evaluateDishDietaryConflicts()`, `renderDishDietaryMetadataHtml()`), and favorite heart buttons (`renderDishFavoriteButtonHtml()`).

### 1.2 3NF Relational Database, Triggers & ACID Locking
- **28-Table InnoDB Schema:** [`database/schema.sql`](../database/schema.sql) (27 core tables) plus [`database/migrate_food_moods_table.php`](../database/migrate_food_moods_table.php) (`food_moods`) and [`database/migrate_v2_features.php`](../database/migrate_v2_features.php) enforce foreign keys, `CHECK` constraints, `ENUM` state machines, and `utf8mb4_unicode_ci` encoding.
- **Database Trigger & Stored Procedures:** `trg_after_menu_stock_update` (`BEFORE UPDATE` on `menu_items`) automatically sets `is_available = 0` and floors `stock_quantity = 0` when inventory hits zero. `schema.sql` also defines `sp_GenerateDailySalesReport` and `sp_ProcessOrderCheckout`, while [`database/migrate_drop_audit_trigger.php`](../database/migrate_drop_audit_trigger.php) retired the duplicate order-status trigger so PHP transitions write authoritative `updated_by_user_id` entries to `order_audit_trail`.
- **Pessimistic Concurrency Control:** High-contention flows (checkout inventory/coupon/loyalty/`scheduled_slot_caps` locking, cancellation restocks & loyalty refunds, order claiming, FCFS dispatch allocation, OTP delivery, Rider SOS transitions, IMPS cashouts, Z-Reports, support replies, and dish review aggregations) execute inside `dbTransactional()` with `SELECT ... FOR UPDATE` locks in deterministic order to prevent overselling, overbooking scheduled slots, duplicate claims, and deadlocks.
- **Soft-Delete Governance:** Archiving records across `users`, `user_addresses`, `categories`, `menu_items`, `dish_customization_groups`, `dish_customization_options`, `faqs`, `food_moods`, and `coupons` updates `is_active = 0` rather than executing destructive `DELETE`s, preserving historical order, redemption, and audit foreign keys.

## 2. Authentication, RBAC & Multi-Actor Session Isolation

- **Same-Browser Multi-Session Isolation:** `getCurrentPortal()` in [`config/config.php`](../config/config.php) inspects the script path/URI (and for `/api/*`, disambiguates using session cookies, `portal` parameters/headers, or same-host `HTTP_REFERER`) to select distinct PHP session cookies:
  - Customer: `ZIPPY_CUSTOMER_SESS` (`ZIPPY_ACTOR_CUSTOMER`)
  - Kitchen: `ZIPPY_KITCHEN_SESS` (`ZIPPY_ACTOR_KITCHEN`)
  - Delivery: `ZIPPY_RIDER_SESS` (`ZIPPY_ACTOR_DELIVERY`)
  - Admin: `ZIPPY_ADMIN_SESS` (`ZIPPY_ACTOR_ADMIN`)
  This allows simultaneous login as all four roles in separate tabs of a single browser.
- **Role-Based Access Control (RBAC):** Four roles (`1=ADMIN`, `2=CUSTOMER`, `3=KITCHEN`, `4=RIDER`) are enforced via `requireAdmin()`, `requireKitchen()`, `requireRider()`, `requireCustomer()`, `hasRole()`, and the granular `RBAC_PERMISSIONS` map (`hasPermission()`). Order endpoints prevent Insecure Direct Object Reference (IDOR) via `canAccessOrder()` and `isRiderAssignedToOrder()`.
- **Credential Security & Recovery ([`includes/auth.php`](../includes/auth.php)):**
  - Passwords use `password_hash(..., PASSWORD_DEFAULT)` and `password_verify()` with transparent `password_needs_rehash()` upgrades and `session_regenerate_id(true)` on login.
  - Inactive accounts (`is_active = 0`) are blocked from signing in.
  - Offline password reset ([`customer/forgot-password.php`](../customer/forgot-password.php)) uses `lookupUserSecurityQuestion()` and `resetPasswordWithSecurityAnswer()`, verifying normalized answers against `users.security_answer_hash` inside a `FOR UPDATE` transaction.
  - Demo email shortcuts (`resolveEmailAlias()`) are strictly gated behind `APP_DEMO_MODE`.
- **Defense-in-Depth CSRF & XSS Protection:** State-mutating forms and JSON/AJAX requests validate tokens via `verifyCsrfToken()` / `verifyRequestCsrf()` (accepting `$_POST['csrf_token']`, `X-CSRF-TOKEN` headers, or JSON `csrf_token`). Outputs use `e()` and `jsJson()` (`JSON_HEX_*`), while rich FAQ HTML passes through `sanitizeFaqContent()`.

## 4. Kitchen Display System (`kitchen/`)

- **WSJF Prioritized Kanban & Automated Scheduled Pre-Alerts ([`kitchen/index.php`](../kitchen/index.php), `OrderService::getKitchenDashboardData()`):**
  - Splits active tickets across **New (`PLACED`/`CONFIRMED`)**, **Cooking (`COOKING`)**, and **Ready (`READY`)** swimlanes, plus **Advance Scheduled**, **Order History**, and **Chef Salary & Payslips** tabs.
  - Immediate tickets are ordered by [`WSJFQueue`](../includes/WSJFQueue.php) with an FCFS tie-breaker (`placed_at ASC, order_id ASC`); `Ready` tickets are sorted chronologically by `ready_at` (FCFS).
  - `WSJFQueue::getScheduledPreAlerts()` surfaces upcoming advance meals due within prep lead time inside an FCFS-sorted **Scheduled Meal Pre-Alert** banner on the KDS.
- **Kitchen Station Routing & Dish-Level Prep Checklists ([`kitchen/ajax/toggle-item-prepped.php`](../kitchen/ajax/toggle-item-prepped.php)):**
  - Station filter pills (`All Stations`, `Main Kitchen`, etc.) filter swimlane tickets by `menu_items.kitchen_station`.
  - In-Preparation (`COOKING`) tickets provide interactive item checkboxes persisted to `order_items.is_prepped` and `order_items.prepped_at` without triggering full-page reloads mid-prep.
- **Real-Time SSE Push, Polling & Web Audio Chimes ([`api/sse-stream.php`](../api/sse-stream.php), [`kitchen/ajax/poll-orders.php`](../kitchen/ajax/poll-orders.php), [`kitchen/includes/footer.php`](../kitchen/includes/footer.php)):**
  - Subscribes to `EventSource` (`?portal=kitchen`) for `kds_update` events backed by [`getKdsStateHash()`](../includes/functions.php) (tracking status counts, audit events, dispatch failures, and item prep counts), automatically falling back / slowing polling cadence (`20s` when connected, `6s` fallback).
  - Synthesizes a 3-note major triad chime (`523.25 Hz`, `659.25 Hz`, `783.99 Hz`) via Web Audio API (`AudioContext`) when new incoming orders arrive, accompanied by an alert banner, fullscreen kiosk mode, and live ticket search.
- **Ticket Transitions & Auto-Allocation ([`kitchen/ajax/update-status.php`](../kitchen/ajax/update-status.php), `transitionOrderStatus()`):**
  - Advances orders through `CONFIRMED` → `COOKING` → `READY` inside `dbTransactional()` + `FOR UPDATE` locks, logging `order_audit_trail` with the chef's `user_id`.
  - Transitioning to `READY` stamps `orders.ready_at = NOW()` and triggers `autoAllocateReadyOrdersFcfs()`.
- **86-List Stock Control ([`kitchen/ajax/toggle-stock.php`](../kitchen/ajax/toggle-stock.php)):** Lets chefs mark dishes in/out of stock (`is_available = 1/0`) directly from the KDS modal without accessing the full Admin catalog.
- **Thermal KOT Printing ([`kitchen/kot.php`](../kitchen/kot.php), `OrderService::getKitchenKotData()`):** Generates 80mm thermal-formatted Kitchen Order Tickets (`@page { size: 80mm auto; }`) for single or comma-separated batch `order_ids`, highlighting scheduled meal deadlines, customizations, dietary tags, kitchen stations, and special notes.

## 5. Delivery Partner Fleet Portal (`delivery/`)

- **Duty Toggle, SSE Push & Live Dispatch Sync ([`delivery/index.php`](../delivery/index.php), [`FleetService::toggleRiderDuty()`](../includes/Services/FleetService.php), [`api/sse-stream.php`](../api/sse-stream.php), [`api/live-stream.php`](../api/live-stream.php)):**
  - Riders toggle `ON_DUTY` / `OFF_DUTY` (`$_SESSION['rider_on_duty']`), immediately running `autoAllocateReadyOrdersFcfs()` when coming online.
  - Subscribes to `EventSource` (`?portal=delivery`) for instant `delivery_update` refreshes alongside `syncDeliveryApp()` (`15s` when SSE is active, `5s` fallback).
- **1-Driver-1-Delivery Concurrency Policy (`FleetService::claimOrder()`, `isDriverBusy()`):**
  - Locking `orders`, `delivery_dispatches`, and rider `users` (`FOR UPDATE`) prevents a rider from claiming a second order while already fulfilling an active dispatch and prevents race conditions when two riders claim the same ready order.
- **Rider SOS / Failed Delivery Exception Workflow (`FleetService::reportDeliveryIssue()`, [`delivery/includes/footer.php`](../delivery/includes/footer.php)):**
  - `#riderSupportModal` posts `action=report_issue` (`unreachable`, `wrong_address`, `breakdown`, `spill` + rider notes) to [`delivery/index.php`](../delivery/index.php).
  - For `breakdown`, the dispatch atomically returns to the `READY` FCFS pool, clears `rider_id`, and switches the rider to `ON_BREAK`; for other reasons, sets `delivery_status = 'FAILED'` (`failure_reason`, `issue_notes`, `failed_at`), releases the rider's 1/1 active lock, and alerts the Admin triage desk.
- **Turn-by-Turn Navigation & High-Contrast Night Mode ([`delivery/includes/header.php`](../delivery/includes/header.php), [`delivery/includes/footer.php`](../delivery/includes/footer.php)):**
  - Interactive Leaflet navigation modal with turn-by-turn street instructions, live destination-aware route simulator (`POST api/live-location.php` with `action=simulate_step`), 1-tap `tel:` customer dialer, and a persistent **Night Mode** (`body.rider-dark-theme`).
- **Doorstep 6-Digit OTP Verification, Loyalty Award & COD Settlement (`FleetService::verifyDeliveryOtp()`):**
  - Validates the rider-entered code against `delivery_dispatches.delivery_otp` inside `dbTransactional()` + `FOR UPDATE`.
  - On match: transitions `orders.order_status` to `DELIVERED`, credits customer Loyalty Points via `awardLoyaltyPointsForOrder()` (`1 pt per ₹20` eligible spend), settles `PENDING` `COD` payments to `SUCCESSFUL`, marks `money_transactions` (`CUSTOMER_PAYMENT_COD`) as `COMPLETED`, increments `staff_profiles.cod_balance` and `total_orders_handled`, logs `order_audit_trail`, and triggers `autoAllocateReadyOrdersFcfs()`.
- **Earnings Ledger & Instant IMPS Cashout ([`delivery/ajax/cashout.php`](../delivery/ajax/cashout.php), `getRiderEarningsSummary()`):**
  - Aggregates per-trip base fares, distance allowances, and customer `rider_tip` amounts vs. prior cashed-out records, submitting simulated IMPS transfers (`IMPS-YYYYMMDD-XXXXXX`) inside a `FOR UPDATE` transaction.

## 7. Computational & Algorithmic Engines

1. **Apriori Association Rule Mining ([`includes/AprioriEngine.php`](../includes/AprioriEngine.php), [`customer/ajax/apriori-api.php`](../customer/ajax/apriori-api.php)):**
   - Mines frequent itemsets ($k \le 3$, `DEFAULT_MIN_SUPPORT = 0.05`, `DEFAULT_MIN_CONFIDENCE = 0.20`, `DEFAULT_MIN_LIFT = 1.0`, 60-second in-memory cache) from non-cancelled `order_items` baskets.
   - Matches active cart item subsets against rule antecedents to recommend complementary dishes (`getRecommendations()`), falling back to top-rated active items when historical volume is below `MIN_TRANSACTIONS_THRESHOLD = 5`.
2. **Weighted Shortest Job First (WSJF) Kitchen Queue ([`includes/WSJFQueue.php`](../includes/WSJFQueue.php)):**
   - Computes $\text{Job Duration} = \max(5, \text{maxPrepTime}) + (\text{totalPortions} \times 1.5)$ and $\text{Cost of Delay} = \text{elapsedMinutes} \times \text{urgencyWeight}$ (`1.5` for `PLACED`/`CONFIRMED`, `1.2` for `COOKING`, `0.5` for `READY`) and sorts active kitchen tickets descending by $\text{WSJF Score} = \text{Cost of Delay} / \text{Job Duration}$ with an FCFS tie-breaker (`placed_at ASC, order_id ASC`).
   - Advance scheduled orders (`is_scheduled = 1`) remain at low priority (`0.1`) until `minsUntilDue <= jobDuration + 15`, then escalate into `DUE SOON` prep priority and appear in `WSJFQueue::getScheduledPreAlerts()`.
3. **First-Come First-Served (FCFS) Dispatch, Slot Capacity & SLA Triage ([`includes/FCFSQueue.php`](../includes/FCFSQueue.php), `autoAllocateReadyOrdersFcfs()`):**
   - `autoAllocateReadyOrdersFcfs()` locks `READY` orders, `delivery_dispatches`, and `users` (`role_id = 4`) via `FOR UPDATE`, purges invalid/busy allocations, sorts ready parcels chronologically by `ready_at` (then `placed_at`, `order_id`), and assigns at most one parcel per free `ON_DUTY` rider.
   - Scheduled delivery slots enforce FCFS capacity caps (`scheduled_slot_caps`) inside `OrderService::processCheckout()`.
   - `FCFSQueue::getTriageExceptions()` flags `RIDER SOS / FAILED` dispatches, upcoming `SCHEDULED PRE-ALERT` windows, overdue cooking (`elapsed > max_prep`), stalled unconfirmed tickets (`>= 5m`), stalled ready tickets (`>= 8m`), riders holding `>= ₹3,000` COD cash, and dishes with `<= 5` portions left.
4. **Single Exponential Smoothing (SES) Demand Forecast ([`includes/SESDemandForecast.php`](../includes/SESDemandForecast.php)):**
   - Aggregates a trailing 7-day daily sales series per active dish (`is_active = 1`) and iterates $\hat{Y}_{t+1} = \alpha Y_t + (1 - \alpha)\hat{Y}_t$ with default $\alpha = 0.3$ (clamped to `[0.05, 0.95]`).
   - Outputs next-day and weekend (`2.2x`) forecasts, days of supply, stockout risk flags (`current_stock <= forecast_tomorrow * 1.5`), and recommended reorder quantities.
5. **Geodesic Distance, Geofencing & Route Interpolation (`calculateHaversineDistanceKm()`, `FleetService::interpolateRoute()`, [`api/live-location.php`](../api/live-location.php)):**
   - Computes great-circle distances from Indiranagar Kitchen Hub (`12.9784, 77.6408`) to Bengaluru (`560xxx`) customer coordinates (`validateServiceableLocation()`, 12 km max radius) for tiered delivery fee pricing and interpolates multi-waypoint rider telemetry (latitude, longitude, compass heading via `atan2`, remaining distance `km`, and ETA minutes).

## 8. Shared Platform APIs (`api/`) & Verification

- [`api/live-location.php`](../api/live-location.php): Authenticated `GET` returns hub, destination (`delivery_latitude` / `delivery_longitude`), and rider coordinates, polyline waypoints, Haversine remaining distance, ETA, and OTP; CSRF-protected `POST` (`ADMIN` or assigned `RIDER`) supports `action=simulate_step` and `action=update_location`.
- [`api/live-stream.php`](../api/live-stream.php): Role-scoped JSON telemetry stream serving `?portal=kitchen`, `?portal=delivery`, and `?portal=admin`.
- [`api/sse-stream.php`](../api/sse-stream.php): Authenticated **Server-Sent Events (SSE)** push stream (`text/event-stream`) calling `session_write_close()` after RBAC verification and emitting `kds_update`, `delivery_update`, `admin_update`, and `order_update` events to Connected Portals.
- [`api/catalog-sync.php`](../api/catalog-sync.php): Version-hash polling endpoint exposing public-safe category/dish fingerprints to storefront clients and full inventory/empty-category metrics to authenticated `ADMIN`/`KITCHEN` sessions.
- [`api/dish-reviews.php`](../api/dish-reviews.php): Public `GET` returns dish rating distributions and dimension averages; CSRF-protected authenticated `POST` (`action=submit_review`) inserts `dish_reviews` and atomically updates `menu_items.rating`.
- [`api/payment-webhook.php`](../api/payment-webhook.php): External payment callback requiring a valid `X-Razorpay-Signature` HMAC-SHA256 digest (`RAZORPAY_WEBHOOK_SECRET`), updating `payments` and confirming `PLACED` orders atomically.
- [`tests/test_v2_features_unit.php`](../tests/test_v2_features_unit.php): Pure-PHP CLI unit verification suite validating Bengaluru Haversine geofencing, tiered distance fees, loyalty earn/redeem/cap & GST calculations, coupon fallback validation, dietary conflict alerts, `schema.sql` statement splitting, and new deliverable presence.

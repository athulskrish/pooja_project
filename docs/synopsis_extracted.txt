Introduction and Objectives of the Project

Introduction

The “Online E- Commerce Platform for Food Order” helps small restaurants replace phone chaos with a

clean website. Customers see the complete menu with categories like North Indian curries, Chinese

noodles, and fast-food burgers – complete with prices and live-stock counts. They add items to cart, pick

quantities, submit orders, and get a tracking number instantly.

Restaurant staff log into their dashboard to see new orders pop up by time received. They mark status as

“cooking”, “ready”, or “delivered”, add new dishes anytime, update stock levels, and check quick reports

like today’s top sellers or low-stock warnings.

Everything runs on a regular laptop using XAMPP – no internet or hosting needed. HTML and CSS make

pages look professional on phones or computers, PHP handles all the order processing safely, and MySQL

stores customer details, menu, and orders in organized tables.

This project follows the complete software development process: understanding restaurant problems,

drawing flow diagrams and database structures, writing the actual code with security checks, testing

everything works, and writing full documentation.

Objectives

The major objectives of the proposed system are as follows:

To replace phone orders with online menu browsing to cut confusion by 90%.

To let customers build carts and submit orders in 30 seconds.

To give restaurant staff real-time dashboard for order updates and menu changes.

To create MySQL database with proper table links and security rules.

To build responsive pages that work on any phone or laptop screen.

To add login protection and prevent hacking attempts.

To generate simple reports for daily sales and stock alerts.

To make everything run locally on XAMPP for easy demo.

To document full development process with diagrams and test results.

To design for future additions like payments or delivery tracking.

Project Category

The proposed project falls under RDBMS (Relational Database Management System) category with web application development.

PRIMARY FOCUS: RDBMS

The core system uses MySQL database with 4 normalized tables connected by primary/ foreign keys:

Users (customers + admins)

Menu_items (dishes with stock levels)

Orders (customer purchases)

Order_items (links orders to specific dishes)

PHP performs all CRUD operations securely while HTML/CSS displays results through web pages.

Problem Definition, Requirement Specifications / Literature Review / Project Planning and Scheduling

Problem Definition

Most small restaurants still depend on handwritten notes and phone calls to take orders. Staff answer

multiple calls during busy hours, write details in notebooks, and pass them to the kitchen manually.

This old method causes mistakes—wrong orders, duplicate items, and forgotten deliveries. Customers

also face delays while trying to confirm if their order was received or when it will be ready.

There is no proper system to display real-time menus, stock availability, or daily specials. If a dish runs

out in the kitchen, waiters must inform customers individually, creating confusion. Owners cannot easily

track which items sell most, how much revenue they earned in a day, or how much stock is left.

The system uses PHP and MySQL to store data such as customers, menu items, and orders in structured

tables, replacing all manual paperwork. It also ensures security with login authentication and reduces

errors through automation. This project solves real-world restaurant challenges by bringing a fast, clear,

and affordable digital ordering solution that any small restaurant can run locally without needing

expensive software or internet servers.

Existing System

The existing food ordering system is mostly based on traditional methods where customers place orders

by visiting restaurants physically or by making phone calls. Some restaurants maintain separate websites

or social media pages for taking orders, while others depend on third-party food delivery applications.

Features of the Existing System:

Customers order food through phone calls or direct visits.

Restaurant staff manually record and process orders.

Payments are often made in cash or through separate online payment methods.

Order tracking is limited or unavailable.

Menu updates are performed manually.

Limitations of Existing System

The existing system suffers from:

Time-consuming process for both customers and restaurants.

Human errors in recording and processing orders.

Lack of real-time order tracking.

Limited accessibility since customers may need to call or visit the restaurant.

Difficulty in managing multiple orders during peak hours.

No centralized platform for comparing restaurants, menus, and prices.

Inefficient communication between customers, restaurants, and delivery personnel.

Proposed System

To solve this, the proposed “Online E-Commerce Platform for Food Order” converts the entire process

into a simple web-based system. Customers can easily browse menus, choose items, submit orders, and

check status using any mobile or computer browser. The restaurant receives orders instantly in a

dashboard where staff can update each stage (Received, Cooking, Ready, Delivered).

To overcome these limitations, an integrated e-commerce food ordering platform is required that provides:

Online menu browsing

Easy order placement

Secure online payments

Real-time order tracking

Automated order management

Delivery tracking and notifications

This improves customer convenience, reduces manual work, and increases operational efficiency.

Literature Review

The development of online food ordering systems has evolved significantly over the years, driven by the

increasing adoption of e-commerce and digital technologies in the food service industry. Various studies

have explored methods to improve restaurant operations, customer convenience, and order management

efficiency.

Existing research shows online food ordering systems solve manual restaurant problems but vary by

complexity:

1. Automated Food Ordering Systems

Early research by Deore and Shete (2016) focused on web-based food ordering systems that replaced

traditional telephone-based ordering. Their study found that online menu browsing and automated order

processing significantly reduced order errors and improved customer satisfaction. However, these systems

were mainly designed for large restaurants and lacked affordability for small businesses.

2. Android-Based Food Ordering Applications

Adithya et al. (2017) developed a mobile food ordering application that enabled customers to place orders

through smartphones. The system improved order accuracy and customer engagement through ratings

and feedback mechanisms. Despite its advantages, the requirement for dedicated mobile app

development increased implementation complexity and maintenance costs.

3. Online-to-Offline (O2O) Food Delivery Platforms

Research by Johnson and Lee (2021) examined large-scale platforms such as Zomato and similar services.

These platforms integrated online ordering, digital payments, and delivery management. While highly

effective, they often imposed commission charges on restaurants and reduced direct customer interaction,

making them less suitable for small independent restaurants.

4. Web-Based Restaurant Management Systems

Samal and Sindhu (2023) demonstrated that PHP and MySQL-based web applications provide a practical

solution for small restaurants. Their research showed that lightweight systems can efficiently manage

menus, customer orders, and inventory while remaining cost-effective and easy to deploy. This approach

closely aligns with the proposed project architecture.

5. Post-Pandemic Digital Transformation

According to the Food Service Association (2022), the COVID-19 pandemic accelerated the adoption of

online ordering systems. Restaurants increasingly relied on digital menus and online ordering platforms

to maintain business continuity. Studies reported that simple web-based systems with cash-on-delivery

options achieved higher adoption among small and medium-sized restaurants than complex enterprise

solutions.

Data Flow Diagram (DFD)

DFD (Data Flow Diagram) is a graphical representation of how data moves through a system. It shows:

Input data entering the system

Processes that transform the data

Data stores where information is saved

Output data produced by the system

For your Food Ordering E-Commerce Platform, the DFD explains how customer orders are processed and managed.

DFD Level 0

The Level 0 DFD represents the entire Food Order System as a single process and shows how it interacts

with external entities, namely the Customer and the Admin. The customer browses the menu, selects

food items, and places an order through the system. After processing the order, the system sends

confirmation and status updates back to the customer. The admin updates the menu and manages

customer orders. Whenever an order is received, the admin can change its status, and the updated status

is reflected to the customer through the system.

DFD Level 1

The Level 1 DFD decomposes the Food Ordering System into three main processes: View Menu, Place

Order, and Manage Orders. Customers retrieve menu information from the Menu Database, place orders

that are stored in the Orders Database, and administrators manage these orders by updating their status

and maintaining menu information. The system uses three data stores: Menu DB, Orders DB, and Users DB.

DFD Level 2

The Level 2 DFD further decomposes major modules into smaller sub-processes for detailed workflow understanding.

Modules and Description

The proposed application consists of multiple interconnected modules and sub-modules.

Each module is designed independently in order to simplify implementation, maintenance, scalability, and testing activities.

The major modules of E-Commerce Platform for Food Order are:

User Module

Admin Module

Category Module

Menu Module

Order Module

Order Details Module

Payment Module

Delivery Module

User Module

This module is responsible for managing customer registration, login, profile management, address details, and account-related activities. Users can browse menus, place orders, and track their order status.

Process Logic:

User registers by providing personal details.

System validates the entered information.

User account is created and stored in the database.

User logs in using valid credentials.

System authenticates the user and grants access.

User can view and update profile information.

User browses menu items and places orders.

Admin Module

This module provides administrative control over the system. The admin can manage users, categories, menus, orders, payments, deliveries, and generate reports.

Process Logic:

Admin logs into the system.

System verifies admin credentials.

Admin manages users, categories, menus, orders, payments, and deliveries.

Admin monitors system activities and generates reports.

Admin updates record whenever necessary.

System saves all modifications to the database.

Category Module

This module organizes food items into different categories such as Breakfast, Lunch, Dinner, Beverages, Snacks, etc., making it easier for users to browse and search for food items.

Process Logic:

Admin creates a new food category.

System validates category information.

Category details are stored in the database.

Admin can update or delete existing categories.

Menu items are linked to their respective categories.

Categories are displayed to users for easy navigation.

Menu Module

This module stores and manages food item details including item name, description, price, availability status, and category information.

Process Logic:

Admin adds food items to the menu.

System validates item details such as name, price, and category.

Food item information is stored in the database.

Admin updates item availability and prices when required.

Users browse available menu items.

Selected items are added to the shopping cart.

Order Module

This module handles order placement and processing. It records customer orders, order dates, total amounts, and current order status.

Process Logic:

User selects food items and proceeds to checkout.

System calculates the total order amount.

User confirms the order.

Order information is stored in the database.

System generates a unique order ID.

Order status is initially marked as "Received."

Order status is updated throughout the order lifecycle.

Order Details Module

This module maintains detailed information about each order, including food items ordered, quantity, unit price, and subtotal amount for each item.

Process Logic:

System records each item included in an order.

Quantity and unit price of each item are stored.

Subtotal for each item is calculated.

Order detail records are linked to the corresponding order.

System retrieves order details whenever users or administrators view an order.

Order details are used for billing and reporting purposes.

Payment Module

This module manages payment transactions, payment methods, payment status, transaction details, and payment confirmations.

Process Logic:

User selects a payment method.

System displays the payable amount.

Payment information is submitted for processing.

Payment status is verified.

Successful transactions are recorded in the database.

Payment confirmation is sent to the user.

Order status is updated after successful payment.

Delivery Module

This module tracks delivery information, including delivery status, assigned delivery personnel, delivery address, and delivery completion time.

Process Logic:

After payment confirmation, the order is forwarded for delivery.

Delivery information is created and linked to the order.

Delivery status is initialized as "Assigned."

Delivery personnel pick up the order.

Status is updated to "In Transit."

Order is delivered to the customer's address.

Delivery status is updated to "Delivered."

System records the delivery completion time and updates the order status.
